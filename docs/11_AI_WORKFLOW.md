# 11. Работа с Claude

**Версия:** 2.0 · **Дата:** 2026-11-01 · **Статус:** DRAFT-FOR-APPROVAL

## 1. Роли

| Кто | Что делает |
|---|---|
| **Основатель** | Утверждает канон, содержание вех и `[NEW]`-решения; решает спорные вопросы дизайна |
| **Разработчик(и)** | Сборка и запуск в Unreal, оценка «на ощупь», ревью, настройка окружения |
| **Claude** | Пишет код, данные, тесты, документацию; готовит PR; запускает проверки; анализирует логи; предлагает решения и записывает их как ADR |

## 2. Режимы работы

| Режим | Где работает Claude | Что может | Ограничения |
|---|---|---|---|
| **A. Облачный** | Linux-контейнер Claude Code (веб) | Код, данные, тесты, документы, Python-скрипты, `check_docs.py`, PR | Не может запустить UE, собрать проект Win64 и PIE; результат проверяется на машине разработчика |
| **B. Локальный (рекомендуется с M0)** | Claude Code на Windows-машине (VM) в клоне репозитория | Всё из режима A + `tools/build.ps1`, UnrealBuildTool, `UnrealEditor-Cmd -ExecCmds=…`, Automation-тесты, чтение логов, итерации без посредников | Требует установки Claude Code и доступа к репозиторию |
| **C. Мост редактора (позже)** | Режим B + Unreal Python / Remote Control API | Создание ассетов, расстановка объектов, пакетная настройка | Нужны скрипты и проверка; вне M0–M2 |

**Правило.** Заявление «собралось», «тест прошёл», «работает в сети» принимается только вместе с приложенным логом (из режима B или от разработчика).

## 3. Что нужно для режима B (чек-лист на M0)

1. Windows 10/11, UE 5.8.x, Visual Studio 2022 (Desktop C++, Game development with C++), Git, Git LFS, Python 3.11+.
2. Клон репозитория в путь без пробелов (например, `C:\Dev\scavar`); `SCAVAR.uproject` → *Switch Unreal Engine version* на локальную 5.8.x (изменение `.uproject` не коммитить, пока версию не утвердил технический лидер).
3. Установить Claude Code, открыть каталог репозитория; `CLAUDE.md` в корне загрузится автоматически.
4. Проверить: `python tools/check_docs.py` → OK; `tools/build.ps1 -Config Development -Target Editor` → лог в `Saved/BuildLogs/`.
5. Резервное копирование: локальный диск VM не считать надёжным; источник истины — GitHub.

## 4. Правила для Claude в репозитории

Дублируются в `CLAUDE.md`.

1. Перед правкой правил читать соответствующую систему в [04](04_SYSTEMS_SPEC.md) и тесты в [08](08_QA_AND_ACCEPTANCE.md).
2. Изменение поведения → обновление [04](04_SYSTEMS_SPEC.md) и тестов в том же PR.
3. Баланс — только в `data/*.csv`. Таблицы в документах не править руками; запускать `python tools/gen_tables.py`.
4. Новые факты лора — только как `[NEW]` и вынос на утверждение (ADR-020). Не нарушать запреты [02](02_LORE_CANON.md#42-запрещено-в-игре-canon).
5. Любой новый ассет — запись в `data/asset_licenses.csv`.
6. Не добавлять функции вне бюджета правил (P3). Если нужно — записать ADR и обосновать вырезку другой функции.
7. Каждый PR: описание, список затронутых систем, список выполненных AT, логи, обновлённый `CHANGELOG.md`.
8. Не коммитить секреты, бинарные файлы вне LFS, сгенерированные каталоги UE.
9. Слияние в `main` — только после зелёного `check_docs.py` и тестов, покрывающих изменение.
